# Правка списков

## 1. Правка

Файлы — `src/domain/<имя>.yaml` (домены) и `src/ipcidr/<имя>.yaml` (сети), формат — `docs/lists.md`.
Коротко:

- `example.com` — только домен, `+.example.com` — домен и поддомены;
- IP-адрес — только с маской: `198.51.100.7/32`, иначе mihomo его выбросит;
- без пробелов внутри и без ссылок;
- без комментариев: если записи нужно пояснить, это делается в `docs/lists.md`.

Перед добавлением проверить, нет ли записи уже в списке: повтор даёт предупреждение и меняет байты
`.mrs`. Если добавляется `+.example.com`, отдельная запись `example.com` становится лишней.

**Новый список** — это новый публичный адрес `mrs/<имя>.mrs`. Упомянуть его в `docs/lists.md` и
`README.md`. Имя и папку потом не менять: это публичный контракт (папка задаёт тип файла).

## 2. Пуш и сборка

```bash
git add src docs README.md && git commit -m "rules: <что изменилось>" && git push
```

Коммит идёт с noreply-адреса из настроек репозитория — не переопределять.

```bash
gh run list -R nargothrondir/rule-sets --limit 1
gh run watch <id> -R nargothrondir/rule-sets --exit-status
```

Если сборка упала, прочитать аннотации: там файл и причина. Выброшенная mihomo запись, пробел,
несовпадение содержимого — исправить исходник, в `mrs/` руками не лезть.

```bash
gh api repos/nargothrondir/rule-sets/check-runs/<job_id>/annotations --jq '.[] | "\(.annotation_level): \(.path): \(.message)"'
```

Успешная сборка с изменениями делает коммит `chore(rules): rebuild .mrs` от `github-actions[bot]` —
сделать `git pull` перед следующей правкой.

## 3. Раздача

jsdelivr кеширует ветку до 12 часов. Чтобы изменения разошлись сразу:

```bash
curl -s "https://purge.jsdelivr.net/gh/nargothrondir/rule-sets@main/mrs/<имя>.mrs"
```

Проверить, что отдаётся новый файл: сравнить размер или хеш с `mrs/<имя>.mrs` в репозитории.
