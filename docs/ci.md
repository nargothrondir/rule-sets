# Сборка `.mrs`

Workflow `.github/workflows/compile-rules.yml` собирает `src/domain/*.yaml` и `src/ipcidr/*.yaml` в `mrs/*.mrs` и проверяет результат.
На pull request только проверяет, в `main` — ещё и коммитит собранные файлы.

Утверждения ниже подкреплены исходниками [mihomo](https://github.com/MetaCubeX/mihomo) (ветка `Alpha`)
и проверены запуском.

## Закреплённая версия mihomo

`MIHOMO_VERSION` и `MIHOMO_SHA256` заданы явно, «последний» релиз не используется.

Версия формата зашита в заголовок `.mrs`: `MrsMagicBytes = {'M','R','S',1}`, и ядро требует точного
совпадения (`rules/provider/mrs_reader.go`: `invalid MrsMagic bytes`). Если новый mihomo поднимет
формат, сборка «последним» релизом пройдёт, а клиенты со старым ядром молча перестанут читать списки.

Скачанный архив сверяется с `MIHOMO_SHA256`. Контрольных сумм mihomo не публикует; значение взято из
digest, который GitHub хранит для файла релиза, и сверено с собственным замером.

Обновление версии — навык `.claude/skills/bump-mihomo`.

## Проверки

Для каждого исходника:

1. **Эталон** — `payload` через `yq`, без пробелов по краям, в нижнем регистре: так записи понимает mihomo.
2. **Пробел внутри записи — ошибка.** Mihomo принимает `exa mple.com` и хранит как есть.
3. **Повтор — предупреждение.**
4. **Сборка** `mihomo convert-ruleset <тип> yaml`, тип — имя папки (`domain` или `ipcidr`). Любая ошибка — `panic` и ненулевой код
   (`rules/provider/mrs_converter.go`); пустой список — `panic: empty rule`.
5. **Выброшенные записи — ошибка.** Некорректную запись (ссылку, IP без маски) mihomo пропускает
   с предупреждением `skip invalid domain` или `invalid Ipcidr` и **кодом выхода 0**. Предупреждение
   поднимается до ошибки.
6. **Заголовок** — ровно `MRS` + 1 (`MRS_MAGIC`), байт типа совпадает с папкой (`00` / `01`),
   внутренняя версия набора `01` (`SET_VERSION`). См. «Версии и совместимость».
7. **Сверка содержимого.** Если источник — `.mrs`, конвертер не собирает файл, а выгружает записи
   текстом (`mrs_converter.go`, ветка `export to TextRule`). Собранный файл распаковывается и
   сравнивается с эталоном: ничего не потеряно и не добавлено. Домены — построчно; IP-сети — по
   множеству адресов (`tools/compare_ipcidr.py`), потому что mihomo склеивает соседние сети.

## Версии и совместимость

Устройство файла (после распаковки zstd), проверено на собранных списках:

| Смещение | Поле | Проверка при чтении |
|---|---|---|
| 0–3 | `MRS` + версия контейнера `1` | точное совпадение (`rules/provider/mrs_reader.go`) |
| 4 | тип: `0` — домены, `1` — IP | должен совпадать с `behavior` у потребителя, иначе `invalid behavior` |
| 5–12 | число записей | — |
| 13–20 | длина поля `extra` | — |
| 21… | `extra` | **пропускается**: зарезервировано под расширения без смены версии |
| далее | версия набора `1`, затем данные | точное совпадение (`component/trie/domain_set_bin.go`, для IP — `component/cidr/ipcidr_set_bin.go`) |

- Версий две, и обе читатель требует **точно**: старое ядро не прочтёт файл, если поднимут любую.
  Поле `extra` — задел, чтобы расширять формат, не трогая версии.
- С появления формата (июль 2024) обе версии равны `1`, файлы формата с тех пор не менялись.
- Минимальное ядро с поддержкой `.mrs` — **mihomo v1.18.7** (28.07.2024). Более старое не знает
  `format: mrs`.
- Файл, собранный старым mihomo, новое ядро читает — пока версии те же.

## Коммит

- `.mrs` без исходника ни в `src/domain`, ни в `src/ipcidr` удаляется — иначе jsdelivr продолжал бы раздавать устаревший список;
- коммит только если собранные файлы изменились;
- запуски сериализованы (`concurrency`), чтобы два не пушили одновременно;
- из сторонних actions — только официальный `actions/checkout` (v7, Node.js 24).

## Наблюдения

- Сборка детерминирована: одна версия mihomo на Linux и Windows даёт одинаковые байты.
- Повтор записи в исходнике меняет байты `.mrs`, но не содержимое.
